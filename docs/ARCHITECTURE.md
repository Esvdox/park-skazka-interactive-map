# Архитектура решения

## Контур отображения

1. `assets/base.webp` загружается всегда.
2. `data/layers.json` задаёт реестр управляемых слоёв и их координаты.
3. `data/status.json` содержит только публичные операционные статусы.
4. Оверлей отображается, только если итоговый статус равен `open`.
5. Любой неподтверждённый или блокирующий статус оставляет видимой полупрозрачную версию объекта в базе.

## Интерфейс

- «Карта» содержит только карту, температурные пресеты и масштабирование.
- «Поиск» содержит поиск по реестру и ручное тестирование статусов.
- «Параметры» содержит название слоя, условия работы, минимальную температуру и расширяемые дополнительные параметры.

Параметры в текущем прототипе хранятся в `localStorage`. Для промышленной версии их нужно перенести в авторизованный справочник конфигурации.

## Контур интеграции

```text
ТОиР / диспетчер / погода
          |
          v
закрытый адаптер интеграции
  - сопоставление asset_id -> layer_id
  - проверка свежести
  - расчёт погодных правил
  - приоритет блокировок
          |
          v
публичный status.json без персональных и служебных данных
          |
          v
GitHub Pages / CDN / сайт Парка
```

Браузер не должен напрямую обращаться к ТОиР и не должен содержать ключи доступа. Адаптер публикует только идентификатор слоя, итоговый статус, источник и время обновления.

## Приоритет правил

От более сильного к более слабому:

1. аварийная блокировка;
2. ТО или ремонт;
3. ручное закрытие ответственным сотрудником;
4. погодное ограничение;
5. расписание;
6. статус из системы-источника;
7. `unknown` при отсутствии или просрочке данных.

Публичное ручное включение не должно обходить аварийные, технические или погодные блокировки. Текущий UI допускает ручное включение только как локальный демонстрационный режим.

## Что требуется для промышленного контура

- таблица соответствия объектов ТОиР и `layer_id`;
- характеристики каждого аттракциона и утверждённые погодные пороги;
- допустимая задержка обновления и правило перехода в `unknown`;
- авторизованный интерфейс диспетчера;
- журнал изменений статусов;
- мониторинг публикации и резервный канал обновления.
